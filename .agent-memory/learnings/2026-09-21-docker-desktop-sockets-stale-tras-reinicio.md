# Learning — Docker Desktop no arranca tras reiniciar Windows: sockets AF_UNIX huérfanos

[Error] Tras reiniciar el PC, Docker Desktop 4.91 abría la ventana pero el motor nunca levantaba (`docker info` → "cannot find //./pipe/dockerDesktopLinuxEngine"). Un agente de otro proyecto no pudo arrancarlo. El primer intento de arreglo (borrar los archivos con Remove-Item y relanzar en el mismo comando con un bucle de espera) se colgó.

[Causa raíz] El apagado cortó Docker sin cerrarlo limpio (en el log: `backend process exited: exit status 0x40010004`) y dejó sockets AF_UNIX (`*.sock` y `*.sock.stale`) en `%LOCALAPPDATA%\Docker\run\` y `%LOCALAPPDATA%\docker-secrets-engine\`. Al arrancar, el backend intenta renombrar `x.sock` → `x.sock.stale`; como el `.stale` viejo sigue ahí, falla con "The file cannot be accessed by the system" y el backend se cae (`backend crashed` en `%LOCALAPPDATA%\Docker\log\host\com.docker.backend.exe.log`). Windows no deja borrar esos sockets con Remove-Item. Además, un bucle que solo espera a `docker info` nunca termina si el backend ya se cayó.

[Solución] Cerrar los procesos de Docker, **renombrar la carpeta entera** que contiene los sockets (`run` → `run.old-<hora>`, y lo mismo con `docker-secrets-engine`; renombrar la carpeta sí funciona, borrar los archivos no) y relanzar Docker Desktop. Hay que buscar TODAS las carpetas con `*.sock`/`*.stale` a la vez, no de una en una. El bucle de espera tiene que cortar también cuando aparece en el log una nueva línea `backend crashed`, no solo cuando `docker info` responde. Candidato a la skill `environment-readiness`.
